# circuitry v0.9.0 — design

**Theme:** Researcher-first observation, frontier-aligned.

**Date drafted:** 2026-05-22.

**Status:** approved scope, design under user review.

---

## 1. Goal

Land circuitry in the post-2024 mech-interp mainstream by adding three pure-observation primitive families that align with what the field has converged on, without crossing the contract line into causal interventions.

Sourced from a paired investigation: a Gemini Pro senior-researcher consult (recommended causal patching as the top priority) and a literature review of 2024-2026 frontier mech-interp tooling (recommended deferring patching because it crosses circuitry's observation-only contract; instead ship logit-lens KL, induction-score, and SAE load-and-apply). The literature review wins on the patching question for circuitry specifically — patching would require a clean/corrupt cache abstraction the library does not have today, and would amount to a design-doc amendment, which is v1.0 scope.

Research artifacts: `docs/v0.9-research/lit-review.md`, `docs/v0.9-research/lit-review-provenance.md`.

---

## 2. Scope

**In scope (v0.9.0):**

1. **Lens primitive.** `logit_lens_kl(residual, unembed, final_logits, *, layer_norm=None)` — per-layer KL between the logit-lens projection of the residual stream and the model's final logits. Nostalgebraist 2020 logit lens as the zero-cost baseline.
2. **Attention-screening primitives.** `induction_score(attn_pattern, *, seq_len_repeat)` per head (Olsson et al. 2022 prefix-matching probability on a repeated-random-token probe) and `attention_pattern_entropy(attn_pattern)` per head.
3. **SAE workflow.** `load_sae(release, sae_id, device)` (thin wrapper over `sae_lens.SAE.from_pretrained`) and `sae_reconstruction_error(x, sae)` returning `{recon_mse, l0, l1, frac_alive, ce_recovered_proxy}`. SAELens is a hard dependency.

**Explicit non-goals for v0.9 (deferred):**

- Activation / attribution / path patching (intervention surface; requires clean/corrupt cache abstraction; design-doc amendment; v1.0).
- SAE *training* (out of library scope; defer to SAELens).
- Tuned-lens checkpoint loading (v0.10).
- Cross-checkpoint training-dynamics analysis as a distinct subsystem (falls out naturally from per-step logit-lens-KL and induction-score logging).
- Multi-process / distributed support (separately scoped, additive future-work per design.md §11).

**Layering invariants (CI-enforced, preserved):**

- `core/lens.py` and `core/attention.py` are pure functions: no I/O, no `.cuda()`, no imports from `recorder/`, `recipes/`, `writers/`, or `cli/`.
- `sae/` may import `sae_lens` and `torch` only; no upward imports.
- `recipes/llm.py` continues to import from `core/` and add HookPoints; no downward imports.
- `tests/test_layering.py` allowlist updated to add `sae_lens`.

## 4. Public API

### 4.1 `circuitry.core.lens`

```python
def logit_lens_kl(
    residual: ArrayLike,        # (..., d_model)
    unembed: ArrayLike,         # (d_model, vocab) or (vocab, d_model); auto-detect via shape match
    final_logits: ArrayLike,    # (..., vocab)
    *,
    layer_norm: Callable[[Tensor], Tensor] | None = None,
) -> float:
    """KL(softmax(layer_norm(residual) @ unembed) || softmax(final_logits)),
    mean over leading dims (batch, seq).

    `layer_norm`: pass the model's final LayerNorm (e.g. `model.transformer.ln_f`)
    if the architecture applies a norm before the unembed. For HF decoder LMs
    this is almost always required; without it the lens projection is biased.

    Unembed shape auto-detection: compares unembed's two dims against
    `residual.shape[-1]` (d_model). If d_model == vocab (rare; only for
    tiny test models or pathological vocab choices), orientation cannot
    be inferred — the function emits a logger warning and assumes
    `(d_model, vocab)` layout.

    Returns a single Python float. KL computed in float32 regardless of input dtype.
    """
```

### 4.2 `circuitry.core.attention`

```python
def induction_score(
    attn_pattern: ArrayLike,    # (batch, n_heads, seq, seq) or (n_heads, seq, seq)
    *,
    seq_len_repeat: int,        # length of the repeated half of the probe
) -> list[float]:
    """Per-head prefix-matching probability on a repeated random-token probe.

    For a probe sequence `[r_0, r_1, ..., r_{n-1}, r_0, r_1, ..., r_{n-1}]`
    of total length `2 * seq_len_repeat`, an induction head attends from
    position `t + seq_len_repeat` to position `t + 1` (the token that
    followed `r_t` last time it appeared).

    score[h] = mean over t in [0, seq_len_repeat - 1) of
               attn[h, t + seq_len_repeat, t + 1]

    Returns one float per head. Score close to 1.0 = strong induction.

    **Caller contract:** `attn_pattern` must come from a probe forward pass
    on a repeated-random-token sequence of length `2 * seq_len_repeat`.
    Computing this score on attention patterns from real data is not
    meaningful — the prefix-matching geometry only exists in the probe.
    The Recorder integration handles this by running a dedicated probe
    pass per step (see §5).

    **v0.9 limitation:** the Recorder uses a single
    `recipe.induction_probe_seq_len` for all hooks in a recipe. Per-block
    probe length is not supported in v0.9.
    """

def attention_pattern_entropy(
    attn_pattern: ArrayLike,    # (batch, n_heads, seq, seq) or (n_heads, seq, seq)
) -> list[float]:
    """Per-head mean Shannon entropy (nats) of the attention distribution
    over keys, averaged over query positions and batch.

    Returns one float per head. Low entropy → focused head; high → diffuse.

    **Caller contract:** `attn_pattern` must come from the **user's main
    forward pass on real data** — not from the induction-score probe.
    Entropy on random tokens describes the probe, not the model's behavior
    on the workload being recorded. The Recorder integration sources this
    diagnostic from `output_attentions=True` on the user's step (see §5).
    """
```

### 4.3 `circuitry.sae`

```python
def load_sae(
    release: str,
    sae_id: str,
    device: str = "cpu",
) -> "sae_lens.SAE":
    """Thin wrapper over `sae_lens.SAE.from_pretrained(release, sae_id)` that
    moves the result to `device`. Returns the raw SAELens SAE object so users
    can also use SAELens utilities directly."""

def sae_reconstruction_error(
    x: ArrayLike,               # (..., d_model)
    sae: "sae_lens.SAE",
) -> dict[str, float]:
    """Apply `sae.encode` then `sae.decode` to `x`; return a dict with:
      - recon_mse: mean squared error between x and sae.decode(sae.encode(x))
      - l0:        mean number of non-zero feature activations per token
      - l1:        mean L1 norm of feature activations per token
      - frac_alive: fraction of features that fire at least once over the batch
      - ce_recovered_proxy: 1 - recon_mse / variance(x), a proxy for CE-recovered
                            (cheap; not the full forward-pass CE-recovered)

    All values are Python floats. Computation in float32."""
```

### 4.4 Recipe additions (`recipes/__init__.py`)

```python
@dataclass
class Recipe:
    # ... existing fields ...
    sae_checkpoints: dict[str, tuple[str, str]] | None = None
    induction_probe_seq_len: int = 25  # half-length; full probe is 2 * this

    def with_sae(
        self,
        mapping: dict[str, tuple[str, str]],
    ) -> "Recipe":
        """Return a new Recipe with sae_checkpoints replaced (latest-wins).

        Mapping keys are regex patterns matched against resolved
        fully-qualified module names (e.g. r".*\.layers\.8$"). Values are
        (sae_lens_release, sae_id) pairs forwarded to load_sae(...).

        **Does NOT modify activation_diagnostics.** Loading SAEs is cheap;
        running them every step is not (an SAE encode+decode is two large
        matmuls). Users must explicitly add "sae_reconstruction" to
        `activation_diagnostics` to actually pay that cost — keeping the
        performance impact visible at the recipe surface. See the SAE
        opt-in path in §6.

        **Interaction with `.with_prefix()`:** patterns in `mapping` are
        matched against fully-qualified module names **after** any prefix
        from `.with_prefix()` has been applied. Always call
        `.with_prefix()` *before* `.with_sae()` so patterns are written
        against the final module paths.
        """
```

## 5. Recorder integration

`recorder/live.py` gains four new activation-diagnostic dispatchers, each keyed by a string name in the recipe's `activation_diagnostics`:

| Diagnostic name | Tag layout | Cost per step |
|---|---|---|
| `"logit_lens_kl"` | `activation/logit_lens_kl/{block_name}` | 1 matmul per block (cheap) |
| `"induction_score"` | `activation/induction_score/{block_name}/head_{i}` | 1 synthetic probe forward pass per step, shared across **all** hooked blocks |
| `"attention_pattern_entropy"` | `activation/attention_pattern_entropy/{block_name}/head_{i}` | sourced from the user's main forward pass (via `output_attentions=True`); no probe pass — see attach-time wiring below |
| `"sae_reconstruction"` | `activation/sae/{block_name}/{recon_mse\|l0\|l1\|frac_alive\|ce_recovered_proxy}` | 1 SAE encode+decode per hooked tensor |

**Attach-time wiring:**

- For `"logit_lens_kl"`: at attach, resolve the model's unembed (`model.get_output_embeddings()` — works for tied and untied) and final LayerNorm (`model.transformer.ln_f` / `model.model.norm` — best-effort detection by walking the model). Cache both. If unembed cannot be resolved, emit a single WARN and skip the diagnostic (consistent with existing skip behavior for `attention_head_rank`).
- For `"induction_score"`: at attach, set up a synthetic probe input (see "Probe pass" below). HF models accept `output_attentions=True` at call time on the probe forward; recipe author overrides for non-HF models via `selector` returning the attention weights tensor; otherwise WARN+skip.
- For `"attention_pattern_entropy"`: at attach, the Recorder installs a forward-pre-hook on the model that injects `output_attentions=True` into the user's main forward-pass kwargs (HF idiom; transparent to user code). Forward-output-hook on each matched `self_attn` module then captures the attention tensor from the returned tuple. For non-HF models, recipe author supplies a `selector` returning the attention tensor from whatever the model's main pass produces; otherwise WARN+skip.
- For `"sae_reconstruction"`: at attach, iterate `recipe.sae_checkpoints`, call `load_sae(release, sae_id, device=model.device)` for each, store SAE objects keyed by module pattern. SAELens import is at module top (hard dep). Loading failure is fatal: re-raise. **Note:** SAEs are loaded regardless of whether `"sae_reconstruction"` is in `activation_diagnostics`; the step-time dispatch is what actually runs them. This lets users sanity-check checkpoint loading without paying inference cost.

**Probe pass for induction-score (only):**

- Synthetic input: random token ids in `[0, vocab_size)` of shape `(1, 2 * induction_probe_seq_len)`, with the second half a verbatim copy of the first.
- Run in `torch.inference_mode()` on `model.device`.
- Probe input is generated once at attach-time and cached on the Recorder; reused every step.
- Probe pass runs **exactly once per step**, regardless of how many blocks have `induction_score` enabled. At step boundary, after the user's forward+backward but before metric collection, the Recorder runs the probe forward pass with `output_attentions=True` once and harvests attention weights for every block-hook that requested `induction_score`. `attention_pattern_entropy` does **not** use this probe — it sources from the user's main pass (see attach-time wiring above), so its measurements describe how the model behaves on real data.

**Cost note:** For a typical `seq_len=512` user step, the probe pass at `seq_len=50` adds ≈ `50 / 512` × forward-cost ≈ 10%. Within design.md §10's 10% budget. If multi-block diagnostics push over budget, recipe authors can set `every_n_steps` to dilute.

## 6. Recipe diff (stock `llm`)

`src/circuitry/recipes/llm.py`:

```python
HOOK_POINTS = [
    # ... existing 9 HookPoints unchanged ...

    HookPoint(
        source=TensorSource.OUTPUT,
        pattern=r".*\.layers\.\d+$",
        name="block_output",
    ),
    HookPoint(
        source=TensorSource.OUTPUT,
        pattern=r".*\.self_attn$",
        name="attn_pattern",
    ),
]

weight_diagnostics = ["effective_rank", "attention_head_rank"]
activation_diagnostics = [
    "gate_stats",
    "dead_fraction",
    "logit_lens_kl",
    "induction_score",
    "attention_pattern_entropy",
]
gradient_diagnostics = ["norms_per_param", "global_total_norm"]
```

Recipe grows from 9 HookPoints to **11 by default**; **12+ if `with_sae(...)` is used**.

**SAE opt-in path (not in default recipe):**

```python
import dataclasses
from circuitry.recipes import get_recipe

recipe = (
    get_recipe("llm")
    .with_prefix("model.language_model")  # ALWAYS before with_sae
    .with_sae({
        r".*\.layers\.8$": (
            "google/gemma-scope-2b-pt-res",
            "layer_8/width_16k/average_l0_71",
        ),
    })
)
# Explicitly opt in to paying the SAE encode+decode cost per step:
recipe = dataclasses.replace(
    recipe,
    activation_diagnostics=recipe.activation_diagnostics + ["sae_reconstruction"],
)
```

Two-step opt-in is intentional: `.with_sae()` loads checkpoints but does
not run them per step. The user adds `"sae_reconstruction"` to
`activation_diagnostics` to actually incur inference cost — keeping the
cost visible at the recipe definition site.

## 9. Validation plan

Re-run `scripts/smoke_hf_model.py --prefix model.language_model` against Gemma 4 E2B (and Gemma 2 2B for SAE — Gemma Scope does not yet cover Gemma 4). Capture into `docs/observations/2026-05-22-v0.9-gemma-validation.md`:

1. **Logit-lens KL** — confirm monotonic decrease across layers. Report layer-0 KL and layer-N (last block) KL; expect last-layer KL very near zero (residual stream is by-definition close to final logits after the last block, modulo final LN).
2. **Induction-score** — report top-3 heads by score across all layers. Confirm at least one head scores > 0.3.
3. **Attention-pattern entropy** — report per-layer mean entropy. Predict the 7 full-attention layers (4, 9, 14, 19, 24, 29, 34) will have systematically higher entropy than sliding-window layers; confirm or refute.
4. **SAE recon-error** — on Gemma 2 2B with `google/gemma-scope-2b-pt-res` layer 8 width 16k SAE: report `recon_mse`, `l0`, `frac_alive`, `ce_recovered_proxy`.
5. **Wall-clock (default recipe, no SAE)** — v0.8 baseline was 39.6 s on CPU, 1 step. v0.9 default should land under 45 s on the same machine (additional cost: probe pass for induction-score + per-block logit-lens KL matmul + main-pass `output_attentions=True` for entropy).
6. **Wall-clock (SAE opt-in)** — separate measurement with one Gemma Scope SAE wired at layer 8 (`google/gemma-scope-2b-pt-res` width 16k) on Gemma 2 2B. Report delta vs the SAE-off run on the same model. Caveat in CHANGELOG if it exceeds 20% overhead, since SAE is opt-in.
7. **Test count** — confirm `~192 / ~192 / 0` and ruff clean.
