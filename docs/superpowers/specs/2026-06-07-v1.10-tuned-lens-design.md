## 0. Why this, why now

Released line is **v1.9.0**. The v1.5–1.7 SAE-circuit pillar and the v1.8/v1.9 real-model
hardening closed every open correctness finding from the field reports. The single most-cited
*remaining* research-feature gap is the **tuned lens** — design §1 and §8 both explicitly call it
out as "future work" and "the one lens we haven't shipped." It is the natural completion of the
existing lens story (`core/lens.py::logit_lens_kl`) and the highest-leverage self-contained
feature: medium scope, clean fit against the established Recorder / scan / report / CLI surface,
and a clear differentiator (circuitry would be the only training-diagnostics library that fits a
tuned lens *post-hoc on your own checkpoints* and then reports per-layer tuned-vs-logit KL through
the same workflow you already use).

This release also clears the small deferred polish/correctness bucket (see §9).

### What a tuned lens is (and why logit lens isn't enough)

The **logit lens** (already shipped) projects a layer's residual stream directly through the model's
unembedding: `softmax(LN_f(resid_ℓ) @ W_U)`. It is parameter-free but biased — early/mid layers
live in a different basis than the final residual, so logit-lens KL is dominated by that
representational mismatch rather than by "how much has the prediction formed here."

The **tuned lens** (Belrose et al. 2023, *Eliciting Latent Predictions from Transformers with the
Tuned Lens*) learns a per-layer **affine translator** `h_ℓ ↦ A_ℓ h_ℓ + b_ℓ` (`A_ℓ` initialized to
identity) trained to minimize KL from the lens distribution to the model's *final* distribution.
The translator absorbs the basis mismatch, so the resulting per-layer KL curve is a faithful
"prediction trajectory" — it actually shows where in depth the model commits to its answer. This is
the metric users reach for when studying prediction formation, grokking, and early-exit.

## 1. Scope

**In scope (v1.10):**
1. A pure core primitive `core/lens.py::tuned_lens_kl(...)` — given a residual, a translator
   `(A_ℓ, b_ℓ)`, the unembed, and the final logits, returns the mean KL. Mirrors `logit_lens_kl`
   exactly (orientation auto-detect, float32 upcast, token-axis chunking, device-deterministic,
   no `.cuda()`).
2. A workflow subpackage `circuitry/tuned_lens/` (mirrors `circuitry/patching/` layering):
   - `TunedLens` — a serializable container of per-layer translators (`A`, `b`) + the resolved
     `d_model` / layer count / model fingerprint, with `.save(path)` / `.load(path)`.
   - `fit_tuned_lens(model, batches, *, layers=None, steps=250, lr=1e-3, ...) -> TunedLens` — the
     post-hoc trainer (the only optimizer loop in the library; lives in the workflow layer, never
     in `core/`).
3. Recorder + scan integration: a new opt-in activation diagnostic `tuned_lens_kl`, emitted
   per-layer (`activation/tuned_lens_kl/<layer>`) when a fitted `Recipe.tuned_lens` is supplied,
   reusing the existing block-output activation capture and `_LensMeta` unembed/LN resolution.
4. `Recipe.tuned_lens: TunedLens | None` field + `llm` recipe documents how to enable it
   (opt-in, NOT in the default diagnostic list — it requires a fitted lens).
5. Report integration: `tuned_lens_kl` added to `HERO_SECTIONS`; a `tuned_lens_not_forming`
   FLAG_RULE (final-layer tuned KL still high ⇒ prediction never sharpens).
6. CLI: `circuitry fit-tuned-lens` (train translators from a checkpoint/model spec → `.pt`).
7. The §9 polish bucket.

**Out of scope (deferred):**
- Live *training* of the lens inside the `Recorder` loop. Fitting is post-hoc only — it needs many
  forward+backward passes and would blow the §10 ≤10% wall-clock budget. The Recorder only ever
  *applies* a pre-fitted, frozen lens (forward-only, like logit lens).
- Causal-basis extraction / the tuned-lens "prediction-trajectory" curvature analyses from the
  paper. Translators only.
- Per-modality tuned lenses for vision / recsys. LLM-only in v1.10 (the residual-stream→unembed
  structure is LLM-specific); the primitive is modality-agnostic so a future recipe can wire it.

## 2. Public API

### 2.1 Core primitive (`circuitry.core.lens`)

```python
def tuned_lens_kl(
    residual: Any,
    translator: tuple[Tensor, Tensor],   # (A: (d_model, d_model), b: (d_model,))
    unembed: Any,
    final_logits: Any,
    *,
    layer_norm: Callable[[Tensor], Tensor] | None = None,
    chunk_size: int = 256,
) -> float:
    """KL(softmax((LN(A @ resid + b)) @ W_U) || softmax(final_logits)), mean over tokens.

    Pure. float32 upcast, orientation auto-detect + d_model==vocab edge case identical to
    logit_lens_kl. Stays on the input device. `A` defaults conceptually to identity (a tuned
    lens with A=I, b=0 reduces exactly to the logit lens — asserted in tests)."""
```

Refactor note: factor the shared tail of `logit_lens_kl` / `tuned_lens_kl` (orientation
resolve + chunked KL accumulation) into a private `_lens_kl_from_logits(...)` helper so the two
public functions stay a few lines each and can't drift.

### 2.2 Workflow (`circuitry.tuned_lens`)

```python
@dataclass
class TunedLens:
    translators: list[tuple[Tensor, Tensor]]   # one (A, b) per fitted layer
    layers: list[int]                          # block indices these map to
    d_model: int
    model_fingerprint: str                     # guards apply-time mismatch
    def save(self, path) -> None: ...
    @classmethod
    def load(cls, path) -> "TunedLens": ...

def fit_tuned_lens(
    model, batches, *,
    layers: list[int] | None = None,   # default: all resolvable blocks
    steps: int = 250,
    lr: float = 1e-3,
    weight_decay: float = 1e-3,
    device: str | None = None,
    forward_fn=None,                   # reuse Recipe.forward_fn convention
) -> TunedLens:
    """Freeze the model; for each target layer train A_ℓ (init I) + b_ℓ (init 0) by SGD/AdamW
    to minimize KL(tuned-lens || final). Returns a frozen TunedLens. Post-hoc only."""
```

`fit_tuned_lens` captures per-layer residuals via the same block-output hook strategy the recorder
uses, runs the model once per batch to get residuals + final logits, then optimizes the small
affine params (the model stays frozen — only `d_model² + d_model` params per layer train). This is
the only place in the library that builds an optimizer; it lives strictly in the workflow layer.

### 2.3 Recipe field + Recorder

```python
# recipes/__init__.py — new field
tuned_lens: "TunedLens | None" = None
```

When `"tuned_lens_kl" in recipe.activation_diagnostics` AND `recipe.tuned_lens is not None`, the
recorder emits `activation/tuned_lens_kl/<layer>` per block, reusing `_LensMeta` (unembed + final
LN) and the existing block-output activation capture — zero new hooks. If the diagnostic is
requested but `recipe.tuned_lens is None`, warn once at `attach()` ("requested tuned_lens_kl but
no fitted Recipe.tuned_lens supplied; run `circuitry fit-tuned-lens` — skipping") and skip,
mirroring the existing logit-lens "no resolvable unembed" path. A model-fingerprint mismatch
between the fitted lens and the attached model warns and skips (never silently emits wrong KL).

### 2.4 CLI

```
circuitry fit-tuned-lens MODEL_OR_CKPT --out lens.pt [--layers ...] [--steps N] [--lr ...]
```

Loads the model (checkpoint scan-style discovery / import path), runs `fit_tuned_lens`, writes the
`TunedLens` to `--out`. Documented as a one-time pre-step before enabling the `tuned_lens_kl`
diagnostic.

## 3. Layering & invariants (CI-enforced — no contract change required)

- `core/lens.py::tuned_lens_kl` is a pure function. **No** optimizer, no `nn`, no I/O — same as
  `logit_lens_kl`. Keeps invariant #1 (core has no I/O) and #4 (no hidden `.cuda()`).
- The optimizer loop + serialization live in the **new `circuitry/tuned_lens/` workflow package**,
  which may import `core/` (and may be imported by `recorder/` and `cli/`). It MUST NOT import
  `cli/`. Add it to `.importlinter` / `tests/test_layering.py` with the same constraints as
  `patching/`.
- No new root dependency. Fitting uses only `torch` (`torch.optim.AdamW`). `numpy` unchanged.
  The `tests/test_layering.py` allowlist is unchanged.
- `Recipe.tuned_lens` is a forward-referenced optional field; importing `recipes` must not force
  importing `tuned_lens` eagerly (lazy / `TYPE_CHECKING` annotation) to keep `import circuitry`
  lean.

## 4. Performance (§10)

- **Apply-time (live/scan):** `tuned_lens_kl` adds one `(d_model × d_model)` matmul + bias per
  layer per emit step on top of the logit-lens projection it already does — negligible versus the
  existing per-layer `(tokens × d_model) @ (d_model × vocab)` unembed and the shared SVD set. It
  reuses the captured block outputs, so **no extra forward pass**. Expected to stay inside the
  ≤10% budget; re-validate alongside the existing GPU budget run and record the delta in §10.
- **Fit-time:** post-hoc, outside the training loop, explicitly NOT counted against the ≤10%
  budget (same carve-out as the SAE-circuit runners and the drift probe). Cost is
  `steps × batches × (1 forward + small backward over the affine params)`; documented with the
  `steps` / `lr` knobs. Default `steps=250` is a few seconds on a small model, minutes on GPT-2.

## 5. Testing strategy

- **`tests/core/test_lens.py`** — (a) `tuned_lens_kl` with `A=I, b=0` equals `logit_lens_kl`
  bit-for-bit (the reduction property); (b) a translator that exactly maps a mid residual onto the
  final residual drives KL → 0; (c) orientation auto-detect + `d_model==vocab` edge case mirrored
  from the logit-lens tests; (d) device-determinism / no-`.cuda()` guard.
- **`tests/tuned_lens/test_fit.py`** — `fit_tuned_lens` on a tiny toy transformer: fitted KL is
  strictly lower than logit-lens KL on held-out batches (the whole point); `save`/`load`
  round-trips; fingerprint guard rejects a mismatched model.
- **`tests/recorder/test_tuned_lens_diagnostic.py`** — recorder emits
  `activation/tuned_lens_kl/<layer>` when a fitted lens is supplied; warns+skips when requested
  without one; warns+skips on fingerprint mismatch; no hook leak after `detach()`.
- **`tests/recipes/`** — `tuned_lens_kl` is NOT in any default recipe list (it requires a fit);
  `effective_diagnostics()` reflects it once enabled.
- **`tests/e2e/`** — fit a lens on the tiny-LLM example checkpoints → enable the diagnostic →
  `scan_run` → `build_report` contains the tuned-lens hero section.
- **`tests/cli/`** — `circuitry fit-tuned-lens` writes a loadable `.pt`.
- **`tests/test_layering.py`** — `tuned_lens/` obeys the import rules.

## 7. Risks

| Risk | Mitigation |
| --- | --- |
| Fit instability / KL not beating logit lens | AdamW + weight decay, `A` init = I so step 0 == logit lens; test asserts strict improvement on held-out batches; expose `steps`/`lr`. |
| Lens applied to the wrong model (silently wrong KL) | `model_fingerprint` stored at fit time; recorder warns + skips on mismatch — never emits. |
| Scope creep into causal-basis / curvature analyses | Explicitly deferred (§1). Translators only. |
| Layering violation (optimizer in core) | Trainer lives in `tuned_lens/` workflow package; `core/` stays pure; CI layering test extended. |

## 8. Open question (non-blocking)

- **Translator granularity:** full `d_model × d_model` affine (paper-faithful) vs. a cheaper
  low-rank or diagonal translator. Default to the full affine (matches the paper and the test
  oracle); a `rank: int | None` knob on `fit_tuned_lens` is a possible v1.10.x follow-on if the
  full matrix is too heavy at large `d_model`.

## 9. Polish / correctness bucket (bundled into v1.10)

Independent deferred point-fixes, each small, each lands with a test update:

1. **[bug] `build_report` Δ column shows unsigned range, not signed `last − first`.** Deferred
   since v1.2. `recorder/_metrics.py:25-28` (`_stats`) returns `delta = vmax - vmin`; a
   monotonically *decreasing* metric renders a positive Δ, reading like an increase. Fix: return
   `delta = vals[-1] - vals[0]` (signed). Update the `test_report` golden expectations in the same
   commit. The v1.2 `## Flags` block and `compare` already use signed deltas, so this only aligns
   the table.
2. **[debt] `update_delta_vanishing` flag uses a scale-dependent absolute L2 threshold** (`1e-6`
   in `recorder/report.py` `FLAG_RULES`). Normalize by `‖W‖` (or element count) before
   thresholding so the flag means the same thing across matrix sizes. Update the flag's test.
3. **[perf] Optional SVD cost reduction via `eigvalsh(WᵀW)` on the Gram matrix.** Now that v1.8's
   full-SVD default raised per-emit weight-diagnostic cost, extend the existing `use_gram='auto'`
   fast path coverage / lower its rectangularity threshold where it's exact, trading a documented
   accuracy note on the spectral tail for speed on wide weights. Benchmark-gated; only land if it
   measurably helps the §10 GPU number without regressing the rank tests.
